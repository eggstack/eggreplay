## Qualification results

- `.eggr` schema 1 is versioned and validated at open time. A manifest is
  published only after a recording completes; incomplete staging directories
  are not valid sessions.
- Request and response bodies are written and hashed incrementally. Store
  limits default to 64 MiB per body and 512 MiB per session, and the recording
  gateway streams response files in 64 KiB chunks.
- Matching is deterministic, bounded, and consumption-aware, with strict and
  practical profiles, once/repeat-last/unlimited modes, and bounded near-miss
  diagnostics.
- Replay and regression paths use the EggServe, EggFetch, and optional Eggress
  seams. The repository has no second hand-rolled HTTP/TLS network stack.
- CLI output has human, JSON, and JUnit envelopes, stable exit categories, and
  commands for record, offline serve/replay, regression test/diff, inspect, and
  validate.
- Default security behavior redacts sensitive headers/cookies and URL userinfo;
  configured query and structured-body redaction is supported. Fixture paths
  are confined, symlinked blobs are rejected, permissions are private by
  default, and corrupt or oversized input is rejected before use.
- Documentation is present for quickstart, architecture, schema, matching,
  security/redaction, CLI contracts, regression workflows, Eggress routing,
  non-goals, and release process.

## Supported matrix and dependency policy

- Rust 1.89 and stable; edition 2024.
- Direct HTTP/1.1 acquisition and EggServe inbound HTTP/1.1 replay.
- Optional Eggress listener-free outbound TCP routing.
- EggFetch 0.2.0 from crates.io.
- EggServe primitives/server pinned to exact revision
  `859a2bc2fe1d9e6215c122d19cd50f2f070d2da6`.
- Eggress outbound pinned to exact revision
  `c493eab803654d1316150a9837fd01ee46b9b87d`.

The temporary Git pins have a documented removal gate in
`docs/architecture.md`: replace them only when equivalent published crates
provide the required generic streaming, trailer, lifecycle, and typed route
failure surfaces, then requalify the dependency matrix.

## Residual risks and deferred work

There is no hosted CI result in this closure, no benchmark suite, and no
end-to-end external upstream integration test in the local test set. Replay
fixtures load response bodies subject to store limits, and regression response
observations are bounded at 64 MiB. Opaque binary content can still contain
sensitive data unless application-specific redaction is supplied. HTTP/2,
HTTP/3, WebSocket, TLS interception, authored scenarios, streaming timing
profiles, Python bindings, and HAR compatibility remain out of scope.

M009–M014 remain deferred in the registry. They are not unblocked by this
closure because they are future roadmap milestones rather than dependencies of
the v0.1 workstream.
